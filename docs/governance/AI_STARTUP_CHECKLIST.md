# AI Startup Checklist

## Purpose

Provide a consistent startup process for AI sessions.

This checklist helps ensure that project context and governance rules are loaded before work begins.

---

## Step 1 - Load Governance

Read:

- .cline/bootstrap.md
- .cline/roles/*

Understand:

- Workflow
- Role responsibilities
- Role restrictions

---

## Step 2 - Load Project Knowledge

Read:

- PROJECT_CONTEXT.md
- CURRENT_STATUS.md
- KNOWN_ISSUES.md
- INVESTIGATION_LOG.md
- ARCHITECTURE_OVERVIEW.md
- DECISION_LOG.md
- TESTING_STRATEGY.md
- WORKING_AGREEMENTS.md

---

## Step 3 - Determine Current State

Identify:

- Current priorities
- Open investigations
- Known issues
- Pending role validations

---

## Step 4 - Determine Required Role

Select the appropriate role before beginning work.

Do not perform responsibilities that belong to another role.

---

## Step 5 - Follow Governance Workflow

User Request

→ Project Analyst
→ Architect
→ QA Investigator
→ Environment Steward (if required)
→ Developer
→ QA Retest
→ Implementation Manager
→ Repository Steward
→ Release Manager

---

## Principle

The repository is the primary source of project knowledge.

Do not rely on conversation history as the authoritative source of project context.
